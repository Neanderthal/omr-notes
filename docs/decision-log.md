# Журнал решений: набор для распознавания нот (omr-notes + notes-to-piano)

Документ описывает, что и зачем было сделано при построении набора инструментов
для оптического распознавания нот (OMR) и озвучивания партитур. Для каждого
значимого шага — принятое решение и его обоснование, включая тупики и то, чему они
научили.

---

## 1. Контекст и цель

Отправная точка — практическая задача: распознать ноты «Божья коровка» из фото
страницы детского сборника «Музыкальная радуга», получить редактируемую партитуру и
озвучить её. Из этого выросли два навыка Claude Code и целый конвейер.

**Итоговая цель набора:** фото/скан/PDF нот → чистый MusicXML → нотный лист (PDF),
MIDI и фортепианное аудио (MP3). Всё — локально и бесплатно (окружение в России, где
облачные AI-API геоблокированы).

Репозиторий: `github.com/Neanderthal/omr-notes` (маркетплейс-плагин с двумя навыками).

---

## 2. Что построено (обзор компонентов)

**omr-notes** (фото/скан → MusicXML):
- `omr.py` — оркестратор: резка на пьесы → распознавание → QA → ремонт → (фьюжн).
  Режимы `--best`, `--repair`, `--fuse`, `--check`.
- `split_pieces.py` — препроцессинг и резка: deskew, dewarp, binarize, кап 20 МП,
  резка по заголовкам.
- `check_musicxml.py` — структурный QA-чекер (penalty + вердикт).
- `fix_omr.py` — детерминированный ремонт: `--fill`, `--ts`, `--rebar`, `--octave`.
- `merge_movements.py` — склейка «движений» Audiveris в один score.
- `staff_split.py` — общий сплиттер станов.
- `fuse_pitches.py` / `fuse_omr.py` — фьюжн высот (Audiveris-скелет + TrOMR-высоты).
- `detect_ottava.py` — best-effort детектор 8va (только подсказки).
- `export.py` — MusicXML → титульный PDF + MIDI.
- `render_musicxml.py` — рендер для визуальной сверки (verovio).
- TrOMR-запасной движок: `tromr_omr.py`, `tromr_setup.sh`.

**notes-to-piano** (MusicXML/MIDI → аудио):
- `to_piano.py` — MusicXML → MIDI (music21) → WAV (FluidSynth + CC-BY саунд-фонт)
  → MP3 (ffmpeg); опции гуманизации, темпа, нормализации.

## 3. Хронология и решения с обоснованиями

### 3.1. Ручная расшифровка «Божьей коровки»
**Действие:** сняли ноты с фото вручную (кропы, deskew в ImageMagick, чтение по
увеличенным фрагментам).
**Обоснование:** на старте не было OMR-навыка; фото мелкое и с кривизной. Это дало
понимание реальных сложностей (наклон, кривизна страницы, несколько пьес на листе) —
требования к будущему инструменту.
**Урок:** фото книжных страниц почти всегда наклонены/покороблены и содержат
несколько пьес → нужны deskew, dewarp и резка на пьесы.

### 3.2. Навык omr-notes и публикация
**Решение:** оформить как **плагин-маркетплейс** (`.claude-plugin/marketplace.json`
+ `plugin.json`), а не просто папку со скриптами.
**Обоснование:** устанавливается через `/plugin install`, удобно делиться; схему
скопировали с рабочих примеров (`opc-skills`, official), чтобы JSON был валиден.
**Проверка перед публикацией:** греп на личные пути/секреты (чисто), валидность JSON,
копирование реальных файлов (не симлинков).

### 3.3. Баннер для README: геоблок → вектор
**Проблема:** генерация картинки через Gemini/Imagen вернула сетевой 403 (геоблок в РФ).
**Решение:** сделать баннер **векторно** (SVG → PNG через Chromium), а не нейросетью.
**Обоснование:** оказалось даже лучше — текст идеально ровный, без артефактов
нейросети, легко редактируется. **Принцип:** где доступность/качество под вопросом,
детерминированная генерация предпочтительнее.

### 3.4. notes-to-piano (аудио)
**Решение:** `MusicXML → MIDI (music21) → WAV (FluidSynth + SF2) → MP3 (ffmpeg)`,
полностью офлайн.
**Обоснование:** геоблок облачных API; FluidSynth + CC-BY саунд-фонт (YDP/Salamander
с FreePats) — бесплатно и локально. MuseScore сознательно **не** требуется для звука
(обошли баг headless-экспорта, минус зависимость).

### 3.5. Препроцессинг и резка (`split_pieces.py`)
Ключевые решения принимались **по диагностике**, а не наугад:

- **deskew** (выравнивание наклона) — фото наклонены; без этого детекторы плывут.
- **dewarp (кривизна).** Первая версия — центроид линий по колонке — дала абсурд
  (сдвиг 733 px): на странице несколько стопок станов, центр масс скачет.
  **Переписали** на кросс-корреляцию строчных профилей по вертикальным полосам (с
  ограничением сдвига). **Урок:** на многостанных страницах «центроид» не работает;
  нужен метод, устойчивый к нескольким станам.
- **binarize** — чистый ч/б кроп. **Доказано:** Audiveris FAILED→ok на реальной
  странице, когда получил битональное изображение вместо тинтованного цветного.
- **Кап 20 МП** — Audiveris отвергает картинки >20 МП («Too large image»). Целая
  страница в 300 dpi = 28 МП → падала. Добавили авто-ужатие. **Урок:** вылезло на
  реальном прогоне, не из теории.
- **Резка по заголовкам, а не по «большому зазору».** Детектор заголовков сначала
  дробил одну пьесу на 3 (инлайновые ремарки «a tempo» и линии 8va принимались за
  заголовки). **Фикс (по диагностике на реальном листе):** заголовок-разрез требует
  большого зазора сверху (≥1.5% страницы) и минимальной высоты (убить тонкие линии
  8va). Калибровка на реальном 2-пьесном листе.

### 3.6. Разрешение источника: не апскейлить скан
**Находка (ключевая):** PDF «Пастушка» содержал встроенное изображение всего
1500×2101 px. Рендер в 300 dpi **растягивал** его (размытие + перебор 20 МП).
**Решение:** рендерить PDF в ~2× нативного разрешения скана (`pdfimages -list` →
выбрать DPI). **Урок:** перерендер низкого скана в высокий DPI только вредит.

### 3.7. QA-чекер: эволюция критерия
Чекер несколько раз переписывался — это показательная история «честности метрики»:

1. Первая версия пропускала такты с `padding` (music21 помечает неполные такты) →
   **ложные PASS** (маскировала потерю долей).
2. Перешли на сравнение **суммы нот+пауз в такте** с размером такта — честный
   критерий. Вскрылось, что даже «хорошие» распознавания теряли долю в финальных
   тактах.
3. Порог сдвига партий: штрафовать только если ≥ целого такта (1–2 доли — норма:
   затакт, молчащий бас). Учёт затактов (anacrusis).
4. Порог PASS ужесточён до <8.
**Урок:** метрика должна ловить реальную проблему, а не удобную формальность; каждый
«ложный PASS» — повод пересмотреть критерий.

### 3.8. Авто-ремонт: `fix_omr` + `--repair` + `--best`
- `fix_omr --fill` — продлевает «обрезанные» такты (Audiveris теряет последнюю долю).
- `--ts`/`--rebar` — починка неверного размера; `--rebar` переписан на общий
  абсолютный таймлайн всех партий (чтобы станы не разъезжались на долю).
- `--repair` в `omr.py` — применяет **безопасный** `--fill` и оставляет только если
  QA улучшился. `--ts`/`--rebar` оставлены ручными (нужно суждение).
- `--best` — перебор движков/флагов/**разрешения**; QA выбирает лучший вариант.
  **Находки:** `--binarize --dewarp` чинит группировку станов (penalty 186→0);
  но **binarize на низком разрешении ломает группировку** → low-res конфиг без
  binarize. Выбор всегда по объективному QA, а не на глаз.

### 3.9. Склейка движений (`merge_movements`)
**Находка:** Audiveris из-за **отступа строки** бьёт пьесу на `.mvt1/.mvt2`, а старый
код брал только mvt1 (терял бˉольшую часть). **Решение:** склеивать движения
(append тактов). «Пастушок»: было 5 тактов из mvt1 → стало 14 (вся пьеса).

### 3.10. Тупик: Sheet Music Transformer (SMT)
**Попытка:** запустить end-to-end трансформер SMT.
**Результат:** веса грузятся (разобрали полную карту переименования ключей,
missing 0), но **вырожденный выход** (повтор токена) на CPU и GPU, на чистом и
сканированном входе.
**Причина:** репозиторий «переписан под HuggingFace» **после** обучения весов;
опубликованный чекпойнт — гибрид (HF-энкодер + оригинальный декодер), которого нет ни
в одном коммите. Веса совпадают по форме, но forward считается иначе.
**Решение:** остановиться, честно задокументировать, убрать окружение.
**Урок:** в research-репозиториях бывает version drift весов и кода; совпадение форм
весов не гарантирует совпадение вычислений.

### 3.11. Успех: TrOMR как запасной движок
**Почему сработал (в отличие от SMT):** веса лежат **в репозитории**, грузятся строго
(`strict=True`) → код совпадает с весами. Выход связный и точный на чистых строках
(Minuet-требль распознан точно).
**Решения по интеграции:**
- TrOMR — **одностаночный** → написали обвязку `tromr_omr.py`: детекция станов →
  нарезка по ширине → TrOMR по сегментам → склейка токенов.
- **Конвертер семантических токенов TrOMR → MusicXML** (music21): разбор clef/key/
  time/note/chord/rest, длительности с точками, аккорды.
- Отдельное окружение (старые пины); torch 1.11 из репо **не грузится на этом ядре**
  (exec-stack) → ставим torch 2.4.1, который запускает чекпойнт.
**Роль:** именно **запасной** — второе мнение по высотам там, где Audiveris врёт, а
не замена основного пути.

### 3.12. Фьюжн высот (brainstorm → дизайн → реализация)
**Идея:** объединить асимметрию движков — Audiveris хорошо берёт **структуру/ритм**,
TrOMR лучше **высоты**. Оставляем скелет Audiveris, накладываем высоты TrOMR.
**Решения (через брейншторм):**
- Политика: замена **при расхождении, когда выравнивание надёжно** (не трёхстороннее
  голосование — отложено).
- Общий сплиттер режет станы для обоих движков (бесплатное соответствие тактов).
- Выравнивание нот — **Needleman-Wunsch по ритму** (онсет+длительность, не по
  высоте), с порогом по ритмическому расстоянию.
- Пивот по ходу: **Audiveris по одиночному стану ненадёжен** → запускаем Audiveris на
  **всей системе**, TrOMR — по станам, сопоставляем по порядку.
- **Критичный фикс:** структурный QA **не ловит порчу высот** — вслепую фьюжн менял
  55/124 ноты на чистом Минуэте. Добавили **гейт по согласию**: правим только если
  TrOMR уже совпадает с Audiveris на ≥80% нот (тогда расхождения — достоверные
  правки); иначе партию пропускаем. **Урок:** нельзя полагаться на метрику, которая не
  измеряет именно то, что меняешь; гейтим по кросс-движковому согласию.

### 3.13. 8va/ottava
**Находка:** даже когда Audiveris пишет `octave-shift`, music21 **не** превращает его
в рабочую Ottava → сдвиг теряется.
**Решение:** разделить на **надёжное применение** (`fix_omr --octave 'P:A-B:+1'`,
детерминированно) и **best-effort детектор** (`detect_ottava.py`, только подсказки,
никогда не правит — ложное срабатывание не испортит партитуру).
**Урок:** фрагильную детекцию отделяем от применения; применение — явное и безопасное.

## 4. Сквозные принципы (что усвоили)

- **Диагностика перед фиксом.** Почти каждый фикс (dewarp 733px, кап 20 МП,
  over-split, resolution) рождался из разбора реального сбоя, а не из теории.
- **Проверять содержимое, а не имя файла.** `telegram-search` перекачал файлы и сдвинул
  нумерацию — долго скармливали Audiveris обложку вместо нот. (Записано в память.)
- **Переиспользовать уже сделанное.** В длинной сессии искать готовые артефакты, а не
  перезапускать тяжёлый пайплайн. (Записано в память.)
- **Честные метрики и гейты.** Ложные PASS чекера и порча высот при фьюжне — оба раза
  причина в том, что метрика не измеряла суть. Гейтить по тому, что реально важно.
- **Детерминированное > нейросетевое, когда можно.** Баннер, препроцессинг, ремонт,
  применение 8va — предсказуемо и без геоблока.
- **Безопасность важнее охвата.** Пороги фьюжна/ремонта выбраны так, чтобы **не
  навредить**; где не уверены — пропуск с откатом на исходное.
- **Честные границы в доках.** Каждая возможность снабжена разделом «что НЕ умеет».

## 5. Текущее состояние, что работает, границы

**Работает хорошо:**
- Чистые типографские PDF (Minuet) — распознаются почти идеально с первого прохода
  (`--best --repair`), дальше `export.py`/`notes-to-piano`.
- Умеренные сканы/фото — `--best` подбирает движок/флаги/разрешение, `--repair`
  дочищает, QA объективно ранжирует.

**Границы (честно):**
- Плотные низкоразрешённые сканы (насыщенные шестнадцатые, 8va) — высоты/ритм частично
  врут; это предел OMR, а не баг. Помогают: лучший источник, ручная правка в MuseScore,
  фьюжн (где движки согласны по ритму).
- TrOMR — одностаночный, станы не всегда выравниваются; детекция станов трудна на
  сверхплотной графике (есть `--staves N`).
- Фьюжн помогает только там, где Audiveris и TrOMR согласны по ритму.
- Битые репризы от OMR роняли экспорт MIDI (обошли удалением; кандидат на хардинг
  `export.py`/`to_piano.py`).

## 6. Хронология коммитов (ориентир)

Начальный релиз навыка → баннер → notes-to-piano → dewarp/binarize → 20 МП-кап →
склейка движений → QA-чекер + `--check`/`--best` → хардинг чекера + `fix_omr` +
workflow → авто-ремонт/aligned-rebar/`export.py` → анти-дробление заголовков →
перебор разрешения в `--best` → TrOMR-запасной → дизайн фьюжна → реализация фьюжна →
`--fuse` + гейт по согласию → `staff_split` (5-chunk + `--staves`) → 8va-хендлинг.

(Точные хэши — в `git log`; дизайн фьюжна — `docs/plans/2026-10-02-pitch-fusion-design.md`.)
